# Change list (2026-08 round)

where a decision was made. Both platforms (native + web) must be checked for
anything controller- or SHM-side.

| 1 | Faces per object, one that allows you to win | dropped | Not needed (2026-08-22). |
| 2 | Background/foreground textures configurable per level | done | 2026-08-22. Four new `fixed` keys — `platform_texture` / `platform_color_mask` (ground plane) and `background_texture` / `background_color_mask` (curved wall). Texture is a `Texture` enum index, mask is `[r,g,b,a]` with `a` as strength (`0` = bare texture, so old files look identical). They are SHM fields with the same names, so they flow through `expand_flat_trial` / `buildTrialState` with no conversion code. Game side: `Backdrop` marker on the two entities, `apply_backdrops` in `setup_round` rewrites each material in place (no asset churn). Defaults in `backdrop_constants` (constants.rs), exported to both controllers and the editor. Editor has a "Background" section between Objects and Trials; `enforceLevel` backfills. Logs: per-frame schema unchanged; `trial_config` picks the keys up automatically and `level_config.background` records them per level run. Default `trials.jsonl` rewritten with a yellow mask ramping 0 → 0.7 across the 9 levels. |
| 3 | Particles always active + controllable | done | 2026-08-22. Second, always-on mote pool in [fog.rs](game_node/src/utils/fog.rs) (`AmbientMote`, `setup_ambient_motes`, `update_ambient_motes`), drifting in a ring in front of the back wall. Density = the consecutive-correct streak, pushed as the new `correct_streak` shared-memory field and reset to 0 at every level change. All tuning is in `ambient_particle_constants` in constants.rs (steps, min/max count, wall gap, inner radius, height band, size, speed, glow, color) — nothing per-level, nothing in the trial editor. Pool is spawned once at startup; density only toggles scale, so no spawn/despawn churn. Hidden while the black screen is up. Motes only spawn in the `AMBIENT_ARC_DEG` arc facing the camera, use a low-poly sphere and are `NotShadowCaster`/`NotShadowReceiver`, so the pool stays cheap. |

| 5 | Left bar = average trial position | done | 2026-08-22. `sum(chain_idxs) / (n_trials × n_objects)` sent as `score_bar_value`/`score_bar_max` over a fixed 1000 scale (`LEVEL_PROGRESS_SCALE`), so the game side is untouched — full bar = level complete. `fixed.score_bar_max == 0` still hides it. The old ±1 health value is gone from the bar but the counter survives as `correctStreak` / `self.correct_streak`, seeded 0, reserved for particle density. |

The session clock moved down to sit under the chain. |

Anchored at the first trial start, the same anchor the `MAX_SESSION_DURATION` cap already used — so the clock sits full during the first break and matches the cap exactly. New live SHM f32 `session_time_left` (fraction left, `<0` hides) written per tick by both controllers; game draws it as a conic gradient in [ui.rs](game_node/src/utils/ui.rs). On web the break screen is a DOM overlay over the canvas; its black backdrop is now dropped as soon as the game reports `is_blank` (`setOverlayOpaque`), so the one game-side clock is visible on both platforms. Radius in `game_constants::SESSION_CLOCK_RADIUS_PX`. Native side not yet compiled/verified. |

| 12 | Win recorded as a bool, not `idx + 1` | done | 2026-08-22. The chain position is stored as `(idx, chain_last_beaten)`: `idx` never leaves `[0, n-1]`, the flag carries the completion. `_chain_pos()` reconstructs the old `0..n` position for every completion/progress computation, so that logic is unchanged (verified by simulating both models over 180k transitions — all observables identical). `_trial_idx()` now feeds only logs/filenames/prints. New log field `trial_chain_completed` (trial log + `trials_runs[]` row), true on the run that beat the chain's last trial. Rule change on top: RETROCEED now steps back from the trial actually played (`_retroceed_pos()`), so a completed chain drops to the trial *before* its last one instead of replaying the last one. |
